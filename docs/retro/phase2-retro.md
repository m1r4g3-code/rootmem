# Phase 2 Retrospective — Consolidation, Salience & Bayesian Belief

**Status:** Filled in after `v0.2.0-phase2`'s automated exit-criterion test, full unit/integration suites, and a live manual dogfooding pass (including a full client restart) all passed on 2026-09-18.

Per the charter's chained SDLC, these findings are an explicit input to Phase 3's research memo — Phase 3 owns episodic→procedural and failure→lesson distillation plus the SKILL.md format, both deliberately deferred out of this phase by the user's own scope decision.

## What shipped

- A Beta-Bernoulli Bayesian belief update (`extraction/contradiction.py`) replacing ADR 0008's flat confidence-floor rule — one `apply_evidence` function serving four call sites (initial creation, corroboration, candidate contradiction, explicit feedback), closing two real Phase 1 gaps in the process: `extraction/contradiction.py` now actually exists (ADR 0008 promised it, Phase 1 never created it), and a repeated identical fact now corroborates instead of silently superseding.
- Salience scoring (`consolidation/salience.py`) — novelty, importance, repetition, computed in batch at consolidation time from one shared pgvector self-join.
- Similarity-threshold union-find clustering (`consolidation/clustering.py`, ADR 0015) for episodic→semantic distillation, empirically validated against real `voyage-4` embeddings before being locked in.
- The consolidation trigger and orchestration (`consolidation/trigger.py`, `consolidation/distill.py`) — no new worker infrastructure (ADR 0012): an inline auto-trigger inside `ingest_session` plus an explicit `consolidate` MCP tool/CLI, both sharing one `maybe_run_consolidation` implementation.
- `ConsolidationRepository` as a new, separate storage Protocol (ADR 0016), and five new `MemoryRepository` methods supporting the batch/salience/clustering pipeline.
- `DistillationProvider` (ADR 0009's pattern extended), with a real Anthropic-backed implementation and a scripted fake.
- A new `feedback` MCP tool (ADR 0014) — the literal, concrete answer to what ADR 0008 called "retrieval-outcome feedback."
- The server now exposes 9 MCP tools (added `consolidate`, `feedback` to Phase 1's 7).
- `tests/integration/test_phase2_exit_criterion.py` — proves corroboration, distillation-driven derivation upgrade, salience, Bayesian contradiction resistance, and feedback all working together end-to-end, real Postgres/Voyage/Anthropic, no fakes.
- A full manual dogfooding pass, including a real client restart, all 7 checklist items passed.

## What worked

- **The contract-test pattern caught a real bug again, exactly as designed.** The Postgres corroboration branch updated `belief_alpha`/`belief_beta` but forgot to recompute the cached `confidence` column — the in-memory fake computed it correctly by construction, so only the real-Postgres integration suite caught the discrepancy. This is the same class of gap the pattern caught in Phase 1 (the `related()` recursive-CTE bug) and Phase 0 (the `REAL` vs `DOUBLE PRECISION` confidence-precision bug) — three phases running, three real bugs, same testing discipline each time.
- **Writing the exit-criterion test itself surfaced a genuine design gap before any code shipped around it.** Trying to write a test proving requirement (a) — "distillation records `derivation=\"distilled\"`" — revealed that `ingest_session` always extracts per-episode facts immediately, so corroboration would always fold into the *first* relation without ever changing its `derivation`, making the requirement structurally unobservable as originally scoped. Fixed properly (a one-way derivation upgrade on corroboration by distilled evidence) rather than working around it in the test. This is the second time in this project a test-writing pass, not implementation work, found the more important bug (the first was Phase 1's search-vs-graph-currency architectural gap).
- **The empirical spike-before-ADR discipline paid for itself concretely.** `scripts/spike_similarity_clustering.py` didn't just validate `distillation_similarity_threshold=0.80` — it found a real near-miss (a same-predicate-different-subject pair at `0.795` similarity, `0.005` below the chosen threshold) that became ADR 0015's own documented, named revisit trigger, not a hidden risk.
- **Reusing already-validated real embeddings, not just similar wording, in the exit-criterion test paid off.** Using the exact three sentences the spike had already proven cluster correctly (not just "similarly worded" sentences) meant the expensive, real-API exit-criterion test's clustering behavior was never itself in question — the only real unknowns were the Bayesian math and the MCP wiring, which is exactly what the test was for.

## What didn't work / surprises

- **The first Bayesian contest-vs-supersede framing was wrong, caught by unit tests before ever touching Postgres.** The initial design (`new_confidence > old_confidence + margin` to supersede) made two equal-confidence single-shot facts always tie and contest — breaking the ordinary "state a fact once, then correct it once" case Phase 1 handled fine, and contradicting the exit criterion's own intent. Fixed by flipping the comparison (contest only when the *old* belief is meaningfully stronger; new evidence wins ties by default, matching Phase 1's most-recent-wins baseline for the routine case). Caught immediately by a unit test's assertion failing — the cheapest possible place to catch a math design error, well before any real-API cost was spent on it.
- **The inline consolidation auto-trigger fires on literally the very first `ingest_session` call into any brand-new namespace**, since a namespace with no prior consolidation run is always time-eligible by design (`consolidation/trigger.py`'s own `should_consolidate`). This silently consumes that first episode as a solo pass (too small to cluster with anything) before its near-duplicate siblings even exist, which surprised both the exit-criterion test and the manual check's own expectations at first. Not a bug — a real, documented consequence of the design worth knowing about — but it means "the first episode in a namespace never gets to cluster with what follows it a few seconds later" is a genuine, permanent property of this system, not just a test artifact. Worth watching in Phase 3+ if it turns out to matter for real usage patterns.
- **Two genuine wire-format testability gaps, found only by trying to write the exit-criterion test, not by planning ahead.** Neither `RelationView` (missing `source_memory_ids`) nor `MemoryView` (missing `salience_score`/`importance_flag`/`consolidated_at`) exposed the very things the exit criterion's own written requirements demanded be "provable via `related`"/"provable via `recall`." Both fixed before the test could even be written meaningfully — a reminder that requirements phrased as "provable via X" are themselves a testable claim about the wire format, not just the internal logic.
- **A real, if narrow, client-side finding during the manual dogfooding pass**: after the MCP server reconnected with the new tools, `consolidate` and `feedback` (brand-new tool names) got fresh schemas immediately, but `ingest_session` (a pre-existing tool name that merely gained a new `importance_flag` parameter) initially displayed a stale schema without it. Calling it anyway worked correctly — the server-side code was never wrong — confirming this was a narrower, per-tool variant of Phase 1's own "MCP tool lists are fetched once, not live-refreshed" finding, this time affecting an existing tool's *parameters* rather than the tool list itself.
- **My own exit-criterion test had two bugs, not the code**: `recall` calls omitting `namespace` (silently defaulting to `"default"` and finding nothing), and an incorrect assumption that all four episodes would remain unconsolidated by the time of an explicit `consolidate(force=True)` call, when the inline auto-trigger (see above) had already consumed the first one. Both are the kind of mistake that real end-to-end testing is supposed to surface — the fix was to correct the test's understanding of real system behavior, not to change the system to match a wrong assumption.

## Decisions to revisit in Phase 3

- Whether `consolidation_episode_threshold`/`consolidation_time_window_hours`'s defaults (500 / 24h, carried over unchanged from the Build Reference's own suggestion) are right at real usage scale — still no real usage data to argue for different numbers.
- Whether the Bayesian reliability weights and `bayesian_prior_strength`/`bayesian_supersede_margin` need calibration now that `feedback` exists and could, in principle, start generating real retrieval-outcome data to calibrate against — this was ADR 0008's own named condition for revisiting, and the mechanism now exists, but no real feedback volume does yet.
- Whether the inline auto-trigger's "first episode goes it alone" property (see above) needs a design change once Phase 3's procedural/failure-lesson distillation adds more consolidation-adjacent traffic, or whether it stays a harmless, well-understood edge case.
- Episodic→procedural and failure→lesson distillation, and the SKILL.md format they depend on — explicitly this project's next scope, deferred here by the user's own decision, not an oversight.

## Metrics captured

- Exit-criterion test wall time: 124.84s, including a deliberate 35s rate-limit-pacing sleep (five real Voyage embedding calls total, paced the same way Phase 1's exit-criterion test was).
- Manual dogfooding pass salience numbers (real, not fixture): flagged-important novel fact scored `0.667`; routine redundant restatement scored `0.123` — over 5x difference, comfortably distinguishing the two cases the formula was designed to separate.
- Real corroboration confidence trajectory observed live: `0.839` (after 3 extraction-time corroborations) → `0.863` (after the 4th, distillation-sourced corroboration) → `0.890` (after explicit `feedback(confirmed)`) — each step measurably higher than the last, never plateauing or resetting.
- `scripts/spike_similarity_clustering.py`: `distillation_similarity_threshold=0.80` exactly reproduces the expected clustering on real `voyage-4` embeddings, with a documented `0.005` margin above the nearest confusable (same-predicate-different-subject) pair.
