# ADR 0008: Contradiction resolution — deterministic rule now, Bayesian math deferred to Phase 2

**Status:** Accepted
**Date:** 2026-09-16

## Context

The charter's algorithm-innovation directives (§5.5) assign "confidence-weighted Bayesian update" contradiction resolution specifically to Phase 1, once the semantic store first has facts that can conflict — which it now does. But Phase 0's own math-spec refused to design salience, decay, or ranking formulas prematurely, on the grounds that a formula invented with no real signal to validate against would likely be thrown away or substantially rewritten once the relevant phase actually existed. The same objection applies here: there is no retrieval-outcome feedback loop yet (did trusting the "winning" relation actually lead to correct answers later?) to calibrate a genuine Bayesian posterior against.

## Decision

Ship a minimal, deterministic contradiction rule in Phase 1, isolated as a pure function (`extraction/contradiction.py`) so Phase 2 can replace it without touching the pipeline around it:

Given a newly-extracted relation for a `(namespace, subject_entity_id, predicate)` that already has an active relation:
- If the new relation's confidence exceeds `contradiction_confidence_floor`: the old relation is superseded (`valid_to` set, `superseded_by`/`supersedes` linked — see ADR 0006's schema).
- Otherwise: both relations are marked `metadata.contested = true` and remain active — neither is silently chosen.

Detection and the soft-supersede mechanics ship now (the graph is useless without them); the sophisticated Bayesian math is deferred to Phase 2.

## Rationale

This makes no claim about which fact is more likely *true* — only about which one the graph should treat as current going forward, with an explicit escape hatch (`contested`) for low-confidence cases rather than a wrong-feeling silent overwrite. It requires no training data, no calibration, and no assumptions about the shape of confidence distributions the system hasn't observed yet. Building the real Bayesian update now, with zero data on how often this simpler rule actually gets contradictions wrong, would mean designing a formula this project has no way to validate — exactly the premature-design risk Phase 0's math-spec already refused to take for salience/decay/ranking.

## Alternatives considered

- **Full confidence-weighted Bayesian update now**, per the charter's literal Phase 1 assignment. Rejected: no retrieval-outcome feedback loop exists yet to calibrate a posterior against; this is a meaningfully larger and riskier scope add with no way to validate the result.
- **Always most-recent-wins, no confidence floor or contested state.** Rejected: silently overwriting a high-confidence fact with a low-confidence one loses information the graph should instead flag, not discard.

## Consequences

- `docs/math-spec/phase1-math-spec.md` documents the deterministic rule explicitly as provisional, with the real Bayesian math's home named as Phase 2 — the same honest framing Phase 0's N/A math-spec used.
- Phase 2's research memo inherits an open question: how often, in practice, does the deterministic rule produce `contested` cases, and does `contradiction_confidence_floor` need tuning — real data this ADR's approach will have generated by then, which a from-scratch Bayesian design today would not have had.
- This is a deliberate, documented deviation from the math-spec's original Phase 1 assignment for contradiction resolution — recorded here rather than silently reinterpreted.
